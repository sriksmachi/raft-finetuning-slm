### Best practices continued

#### Understand Account recovery (ACR) capabilities
When utilizing Single Sign-On (SSO), ensure that at least one Account Recovery (ACR) administrator is registered prior to activation. This precaution secures fallback access to critical systems should primary authentication methods become misconfigured or unavailable. Thoroughly document all ACR procedures, limit access strictly to authorized personnel, and regularly audit ACR usage to uphold strong security standards. Restrict local logins for interactive sessions to approved recovery users with MFA enabled and employ ACR solely as a recovery tool to maintain system integrity.

- ACR removes local login options when SSO is active, for example, local database authentication and LDAP authentication.
- ACR controls do not apply to non-interactive access, because local database authentication is often needed for inbound integrations. Instead, use API Access Policies to specify accepted authentication types and criteria for REST and SOAP APIs. Authentication profiles for APIs can also be used with [System or Export Processor access policies](#).
